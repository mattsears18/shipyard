# /do-work

Burns down the issue backlog with a **rolling worker pool**. Keeps `--concurrency` agents in flight at all times. The instant any agent returns, the orchestrator reconciles its result and dispatches a replacement into the freed slot — no batched waits. The **dispatch loop** stops feeding new workers once the backlog and the in-flight set are both empty — but an empty dispatch pool is **not** session completion ([#662](https://github.com/mattsears18/shipyard/issues/662)). The **session** completes only when every workable issue is closed or dispositioned (merged via its PR, or labeled to a genuine human/operator review class) **AND** every PR this session opened is merged (or blocked on a confirmed **external dependency** the agent cannot itself perform — e.g. a secret value only a human can supply). The [end-of-session drain](./do-work/drain.md#end-of-session-drain) drives that tail after the dispatch loop winds down; see [`drain.md`'s termination assertion](./do-work/drain.md#termination-assertion) for the full-completion contract. **Recommended permission posture:** run this session (and its dispatched workers) under Claude Code's Auto mode, not full permission bypass (`--dangerously-skip-permissions`) — see [`do-work-RATIONALE.md`'s "Recommended permission posture"](./do-work-RATIONALE.md#recommended-permission-posture--why-auto-mode-over-full-bypass-763) for why, and how it composes with shipyard's own worktree-isolation + edit-scope hooks. **Runaway-fanout guards:** on a host that runs `/do-work` unattended for extended burndowns — especially one that doubles as a self-hosted CI runner for the target repo — set `CLAUDE_CODE_MAX_SUBAGENTS_PER_SESSION` and `CLAUDE_CODE_MAX_WEB_SEARCHES_PER_SESSION` (harness env vars, default `200` each) as a backstop against a session fanning out subagents or web searches beyond what a normal burndown needs; see [`do-work-RATIONALE.md`'s "Runaway guards"](./do-work-RATIONALE.md#runaway-guards--subagent--web-search-session-caps-764) for the full rationale and recommended values. **Resilience under model-tier overload:** set `fallbackModel` in `settings.json` (Claude Code v2.1.166+, up to three models tried in order) so a transient overload on one tier degrades to an adjacent one instead of failing a dispatch outright — see [`do-work-RATIONALE.md`'s "fallbackModel"](./do-work-RATIONALE.md#fallbackmodel--degrade-gracefully-under-model-tier-overload-766) for the recommended chain (and the `resolve-dispatch-model.sh --fallback-chain` helper that computes it per model family).

## Args

`$ARGUMENTS` may include:

- **--repo owner/repo** (optional): target repo. Default: `gh repo view --json nameWithOwner -q .nameWithOwner`. If not in a repo, ask via `AskUserQuestion`.
- **--label LABEL** (optional, repeatable): only work on issues with all listed labels. Without it: any open candidate issue.
- **--prioritize-label LABEL** (optional): if provided, issues carrying this label sort ahead of everything else in the backlog — they still pass through normal eligibility (assignee, blocked, linked-PR filters), but get a priority boost above the `P0`/`P1`/`P2` tiers. Issues without the label fall back to the normal ranking. Differs from `--label`, which **filters** the backlog rather than reordering it.
- **--concurrency N** (optional, default `1`): the size of the rolling worker pool — i.e. the number of agents the orchestrator keeps in flight at any moment. Default is `1` (sequential) because the dominant failure mode on most repos is the `plugin.json` / `CHANGELOG.md` / version-row hard-collision under the [steady-state dispatch rules](./do-work/dispatch-rules.md#dispatch-rules-used-by-step-7-and-step-c) — every PR that cuts a release claims the manifest as a HARD path, so a second worker hard-collides the moment any worker is in flight and the second slot sits parked for the rest of the session (see issue [#268](https://github.com/mattsears18/shipyard/issues/268) for the dogfooding rationale). The `C ≥ 2` paths (step 0.7 parallel setup batch, rolling scope pre-flight) only pay off when realized concurrency is actually `≥ 2`; at the steady-state-C=1 most repos hit, those paths are just overhead. Set `--concurrency 2` (or higher) explicitly on repos where most PRs don't bump a manifest/version row and the realized parallelism is real — e.g., a feature-development backlog against a service with no per-PR version bump. **When this flag is omitted and the repo's own merge shape is `ungated`** ([step 1.3's silent-direct-merge detector](./do-work/setup/01-repo-recovery.md#13-detect-the-silent-direct-merge-repo-shape-admin--ungated-merge-config)), a committed `concurrency.default > 1` in `shipyard.config.json` is clamped to `1` rather than honored — the merge shape that produces `ungated` cannot support the version/CHANGELOG coordination C≥2 relies on, so a config default asking for it would just recreate the leapfrog the detector warns about ([#733](https://github.com/mattsears18/shipyard/issues/733)). An explicit `--concurrency N` on the command line always overrides the clamp — you're asking for it by hand.
- **--soft-collision-concurrency N** (optional, default `3`): the cap on how many in-flight workers may simultaneously claim any **soft-collision** path (additive docs files — see [Dispatch rules](./do-work/dispatch-rules.md#dispatch-rules-used-by-step-7-and-step-c)). Set to `1` to opt out of soft-collision tiering entirely (every path collision becomes hard). Set higher to allow more parallelism on docs-heavy backlogs at the cost of more merge-conflict resolution work for the orchestrator at PR-land time.
- **--soft-collision-path GLOB** (optional, repeatable): extend the default soft-collision path set with additional globs. Defaults to a curated set of additive docs files (see [Dispatch rules](./do-work/dispatch-rules.md#dispatch-rules-used-by-step-7-and-step-c)); these add on top, they don't replace. The effective set is the union of three layers: built-in defaults ∪ `concurrency.soft_collision_paths` from [`shipyard.config.json`](../../../CLAUDE.md#configuration-shipyardconfigjson--layered-overrides) ∪ these CLI flags. Per-repo extension via config (instead of repeated CLI flags) is preferred — see [issue #254](https://github.com/mattsears18/shipyard/issues/254).
- **--fast** (optional): skip non-load-bearing setup steps to reduce startup latency. What `--fast` skips: backlog overview UI (step 2), `/refine-issues` invocation (step 3.5), `blocked:ci` auto-clear sweep (step 3d.1), legacy `blocked:agent` migration / `blocked:agent-soft` sweeps (step 3d.2 sub-sweeps b / c — sub-sweep a was deleted in [#521](https://github.com/mattsears18/shipyard/issues/521)), and both divert checks (steps 4.5a + 4.5b). What `--fast` keeps: config opt-in (0.4), worktree relocation (0.5), repo+user resolution (1), session state (1.5), trusted-author allowlist (1.7), orphan worktree triage (3c), backlog fetch+rank+triage (4), scope pre-flight (6), and dispatch (7). The rolling pre-flight model (step 6) means `--fast` sessions now dispatch the first worker as soon as the fastest scoping agent in the initial batch returns (~5–10 s) rather than waiting for the full batch. When `--fast` is used, the end-of-session summary includes a block listing what was skipped and advisory counts. Use when refinement-candidate issues are present (matched by source-signal scan since the `needs-refinement` label was eliminated per [#520](https://github.com/mattsears18/shipyard/issues/520)) and startup time matters more than acting on them immediately.
- **Autonomous & operator-inclusive by default** ([#661](https://github.com/mattsears18/shipyard/issues/661)): a bare `/do-work` runs the autonomous code loop **plus the browser-operator layer** — there is no flag to turn the operator layer *on* anymore; it is the default. The orchestrator drains an [`operator_queue`](#orchestrator-state) of **browser-completable operator actions** — the work `/do-work` otherwise *defers* (the `agent-console` label / `external-dependency` defer class) plus a proactive [`/my-turn`](./my-turn.md)-style sweep filtered to browser-completable items (close a superseded PR, paste a CI secret, toggle a referenced provider setting, post an unambiguous drafted reply). It drives the user's real, logged-in Chrome via the [operator phase](#phase-routing) (preferring the `claude-in-chrome` extension; see [`do-work/operate.md`](./do-work/operate.md)). Code workers still parallelize per `--concurrency`; **browser actions always serialize on the orchestrator thread** (the real browser is a singleton). The loop also makes **autonomous design / architecture decisions** — it makes the reasonable call and proceeds rather than round-tripping to the human for every choice. **This default extends to issue *scoping* itself, not just in-worker implementation choices** ([#767](https://github.com/mattsears18/shipyard/issues/767)): epics, spikes, and design-needed issues are in-scope autonomous work by default — an epic gets decomposed (see [`06b-scope-carveouts.md`'s `confirmed-non-shippable-as-single-PR` path](./do-work/setup/06b-scope-carveouts.md#designarchitectureepicspike-decisions-are-in-scope-by-default-not-a-defer-reason-767) and [`/decompose-epic`](./decompose-epic.md)), a spike gets run to completion (investigate → design call → decompose/implement), and a design-needed issue gets the reasonable design call made and shipped — none of these are, by themselves, a scope-preflight defer reason. **Widening or granting access, or creating a new credential, is the sole hand-back class — not "touches a security setting" ([#970](https://github.com/mattsears18/shipyard/issues/970)):** an auth/access-control mutation that *increases* what someone can reach (loosening password policy, adding an OAuth redirect URI, granting an IAM binding, enabling a sharing permission) is a safety boundary that outranks the default standing authorization, so it's teed up and handed back rather than auto-driven. A mutation that *narrows* or *revokes* access, *deletes* a value a merged change made redundant, or only *reads* an access-control setting to verify its current value is auto-driven like any other mechanical action — refusing those would leave the system less safe, not more (see [`do-work/operate/03-error-handling-and-safety.md` → Safety](./do-work/operate/03-error-handling-and-safety.md#safety--trust-boundary) and the [security/access-control degradation note](./do-work/operate/01-queue-and-authorization.md#degradation--securityaccess-control-heavy-operator-queue-expected-not-a-failure)). Separately, and regardless of direction, the harness prohibits typing a password, entering/pasting a secret or API-key value not supplied live by the user, or creating a new account — a credential-*rotation* task stays partly a hand-back for that reason, not because it's filed under "security setting." Genuine human-judgment browser items (`needs-human-review`) are likewise surfaced, never auto-actioned. Running `/do-work` is itself standing authorization for browser-completable actions on **session-owned artifacts** — PRs in `session_prs` and issues this session dispatched a worker against (no per-action confirmation; `--dry-run` previews only). **That authorization is this spec's own policy commitment, not a technical override of the Claude Code auto-mode permission classifier** ([#746](https://github.com/mattsears18/shipyard/issues/746)): for a `merge-pr` / `close-pr` item against an **inherited third-party PR** the session never opened or touched (a Dependabot PR is the common case), the classifier evaluates the action independently and can deny it by name — correctly, since closing or merging someone else's PR is outward-facing and irreversible. The operator layer batches every such pending item into **one** `AskUserQuestion` confirmation per session (not one per item) before attempting them, and any denial that still occurs is recorded in `operator_denials` and degrades to an `agent-console` hand-back rather than being retried or silently dropped — see [`do-work/operate/01-queue-and-authorization.md` → Scope of standing authorization](./do-work/operate/01-queue-and-authorization.md#scope-of-standing-authorization--session-owned-artifacts-vs-inherited-third-party-prs-746) and [→ Operator action denied by the harness permission classifier](./do-work/operate/01-queue-and-authorization.md#operator-action-denied-by-the-harness-permission-classifier-746). If no browser backend is reachable, the operator layer degrades to the normal code loop and surfaces operator items as hand-backs (warns, never aborts the loop). **Opt out with `--no-operate` / `--hands-off`** (synonyms) for the rare dispatch-only run — `/do-work` then runs the autonomous code loop **only** (dispatches issue-workers, opens PRs, arms auto-merge) and never drives the browser; `operator_queue` items are surfaced as hand-backs (left on their `agent-console` label / surfaced to `/my-turn`), the [`operate.md`](./do-work/operate.md) phase is skipped, and autonomous design/architecture decision-making is unaffected (the opt-out suppresses *browser operation only*).
- **Lightweight C=1 path.** C=1 is the default and skips a substantial chunk of parallel-coordination machinery via per-step gates throughout the spec. See [`setup.md`'s "Lightweight C=1 path — what's skipped and what stays"](./do-work/setup/00j-c1-path-index.md#lightweight-c1-path--whats-skipped-and-what-stays) for the consolidated index — names every gate (with a link to its owning callout), the steps that **stay** at C=1 (worktree relocation, session-state init, trusted-author allowlist, background cleanup group), and how the inline-trivial fast path stacks orthogonally with concurrency. Closes [#347](https://github.com/mattsears18/shipyard/issues/347).

## Orchestrator state

Across the session, the orchestrator maintains thirteen **hot** mental data structures — read or written on most turns — plus a small three-field refresh tracker, listed below. Fourteen more **cold** structures — each consumed by exactly one (or two closely-related) other phase file(s), not read on every turn — live in [`do-work/orchestrator-state-reference.md`](./do-work/orchestrator-state-reference.md); load that file only when you're in the one phase that owns the structure you need (`main_ci_fix_attempts`, `session_blocked_soft`, `reconciled_agent_ids`, `ci_session_counters`, `primary_leak_counters`, `dispatch_denials`, `operator_denials`, `operator_handbacks`, `stalled_dispatches`, `session_state_degraded_since`, `stale_check_refresh_done`, `version_cursor`, `setup_reap_sweep_denial`, `inherited_draft_prs`). Hold the twenty-seven structures (hot + cold) in your head (or in `TodoWrite` if you prefer durable scratch); together they are the entire state machine. The same structures are **mirrored to a JSON file on disk** (see [Session state file](#session-state-file) below) so the artifact survives turn boundaries, can be inspected by external tools (dashboards, notifiers, a future `--resume <session-id>` flag), and lets the LLM stop re-narrating state in prose every turn. The JSON file is the *durable record*; the working memory is still where dispatch decisions are made — **`session_state_degraded_since` is the one structure that exists because the mirror itself can fall out of sync with that record** (issue [#1302](https://github.com/mattsears18/shipyard/issues/1302)); see its entry in `orchestrator-state-reference.md` for why it deliberately never touches the file it's tracking the health of.

- **`in_flight`**: { slot_id → { kind: "issue" | "fix-checks" | "fix-rebase" | "fix-main-ci" | "fix-failing-prs-batch" | "investigate" | "spike", target: <#N or #M or "main" or "pr-pileup">, claimed_paths: { hard: [...], soft: [...] }, agent_id, model?, version_slot?, started_at?, progress_current?, progress_total?, progress_updated_at? } }. Size is bounded by `--concurrency`. The `fix-rebase` kind is drain-only — never dispatched outside the [end-of-session drain](./do-work/drain.md#end-of-session-drain). The `investigate` and `spike` kinds both target `#N` like `issue` — [`/shipyard:status`](./status.md) treats all three identically for target formatting (`#N`) and per-issue token attribution (`.tokens.per_issue`), since all three dispatch against an issue number rather than a PR ([#797](https://github.com/mattsears18/shipyard/issues/797)). `claimed_paths.hard` and `claimed_paths.soft` partition the paths a worker is touching by collision tier — see the [Dispatch rules](./do-work/dispatch-rules.md#dispatch-rules-used-by-step-7-and-step-c). `started_at`, `progress_current`/`progress_total`, and `progress_updated_at` feed [`/shipyard:status`](./status.md) ([#167](https://github.com/mattsears18/shipyard/issues/167)) — `started_at` is set on dispatch; the progress trio is managed by `session-state.sh set-progress` and defaults to `null` for non-batch workers. **`model`** ([#978](https://github.com/mattsears18/shipyard/issues/978)) is the family alias (`opus`/`sonnet`/`haiku`/`fable`) the [per-dispatch model-resolution rule](./do-work/dispatch-rules.md#dispatch-rules-used-by-step-7-and-step-c) resolved for this slot at dispatch time, or the literal string `"default"` when the resolver returned empty (the shim's frontmatter pin, or the `Workflow` runtime's own default, applies instead) — recorded so a dispatch that silently omitted the resolved model isn't invisible after the fact. `/shipyard:status` renders it as a column; it is NOT independent confirmation of which model the dispatch actually ran on (the harness exposes no such signal) — it records what the orchestrator *intended* and *believed* it dispatched. **`version_slot`** ([#1420](https://github.com/mattsears18/shipyard/issues/1420)) is the coordinated manifest version the [next-available-version computation](./do-work/dispatch-rules.md#dispatch-rules-used-by-step-7-and-step-c) handed this dispatch, recorded so [step B.0](./do-work/steady-state.md#b-release-the-slot) can *release* the slot if the dispatch terminates without ever opening a PR. Absent on any dispatch that carried no coordination paragraph (the common case — a repo with `version_coordination.enabled: false`, or no in-flight manifest bump to coordinate against), and absent by construction on every dispatch that predates #1420; step B.0 treats an absent value as `version_release=skipped` rather than guessing, since a wrong guess here is the one thing that could under-count the floor.
- **`ready_issues`**: priority queue of *scoped* issue candidates — `{ number, claimed_paths: { hard: [...], soft: [...] }, lockfile_sections, rank_key }` — ready to dispatch the moment a slot opens. Populated asynchronously as background scoping agents return results (see [step 6](./do-work/setup/06-scope-preflight.md#6-initial-scope-pre-flight) and [step D sub-step 3](./do-work/steady-state.md#d-periodic-refresh)). `lockfile_sections` is the set of `package.json` (or equivalent root-manifest) sections the candidate is expected to touch — `overrides`, `dependencies`, `devDependencies`, `scripts`, `engines`, `config`, etc. — and replaces the older boolean `touches_lockfile` flag. Empty set means the candidate is not a lockfile-toucher and the section-aware collision rule below is a no-op for it.
- **`scope_bg_count`**: integer count of background scoping agents currently in flight (fired by step 6's initial batch or step D's scope-refill). Incremented when a scoping batch is fired; decremented as each background scope agent completes. Initialized to `0`. Powers the `scope_bg=<s>` token on the invariant line — when `> 0`, results are arriving into `ready_issues` asynchronously, and `parked (scope refill in flight)` is a valid idle reason. When `scope_bg_count == 0` and `ready_issues == 0` and `raw_backlog > 0`, the invariant is broken — fire a background scope burst before ending the turn. **C=1 note:** At C=1 scoping is just-in-time (per-dispatch), not batched, so `scope_bg_count` stays `0` and the per-dispatch just-in-time call is synchronous.
- **`failed_prs`**: queue of red PRs (authored by `@me`) needing fix-checks-only work. Drained after `divert_queue`, before `ready_issues`.
- **`raw_backlog`**: ranked list of issue numbers not yet scoped. Source for refilling `ready_issues`.
- **`divert_queue`**: at most two synthetic high-priority entries that *preempt* normal work — `fix-main-ci` (main's latest CI is red) and `fix-failing-prs-batch` (≥10 open red PRs across all authors). Drained BEFORE `failed_prs`. Repopulated by the divert-checks scan (step 4.5 at setup, step D in steady state). An entry is only repopulated when no in-flight slot is already working that diversion — never two workers on the same diversion.
- **`awaiting_external`** ([#1390](https://github.com/mattsears18/shipyard/issues/1390)): park queue for workers that finished everything they could and are waiting on a **long external job** they already started — a dispatched CI run, an EAS/store build, a deploy. Entries: `{ issue, mode, what, probe, eta, agent_id, worktree_path, parked_at, deadline_at, polls }`. Populated by [step A.1](./do-work/steady-state.md#a1-parse-the-return-string)'s `awaiting-external` branch (which re-validates `probe` through `scripts/validate-awaiting-external-probe.sh` — the orchestrator *executes* this worker-supplied string, so it is re-checked at the trust boundary), re-polled by [step D's sweep](./do-work/steady-state.md#d-periodic-refresh). **Never dispatched from** — entries are resumed (`SendMessage` to `agent_id`, preferred) or expired; the parked worker's worktree is deliberately retained, not reaped, for exactly that reason. Bounded by `awaiting_external.max_hours` (default 2, anchored at the first park), after which the entry degrades to a genuine `blocked:` hand-back. Mirrored to the session-state file and part of the [termination condition](./do-work/drain.md#termination-assertion).
- **`paused_on_environment`** ([#1402](https://github.com/mattsears18/shipyard/issues/1402)): session-wide, at-most-one-active pause — distinct from `awaiting_external`, which parks ONE worker on a job IT started. This pauses the WHOLE dispatch loop when [step C's queue-depth backpressure check](./do-work/steady-state.md#c-dispatch-a-replacement-if-work-remains--mandatory-action) holds a slot AND, after this turn's dispatch decisions, `in_flight` has drained to `paused_on_environment.pause_when_in_flight_at_or_below` (default `0`) — no live worker remains whose eventual completion would otherwise wake the orchestrator for a retry, and the turn would otherwise just end with nothing further scheduled. Entry (nullable, `{ reason, resume_probe_repo, resume_probe_pool_total, resume_probe_multiplier, paused_at, deadline_at }`): populated by [step C's "Session-wide environmental pause" section](./do-work/environmental-pause.md), armed alongside a `Monitor` watch of `scripts/watch-resume-probe.sh` so a future notification exists to resume the loop. Cleared on the watcher's `resumed` line, which re-runs the canonical fresh backlog fetch before resuming dispatch — the same fetch [drain.md's termination-assertion step 4](./do-work/drain.md#termination-assertion) already requires. Bounded by `paused_on_environment.max_hours` (default 4, anchored at the first pause and never extended by a re-pause, mirroring `awaiting_external.max_hours`'s anchoring rule), after which the watcher's `held-timeout`/`error` line degrades the pause to a genuine hand-back. Currently CI-queue-depth-specific — the only environmental-halt detector this repo has wired ([#1156](https://github.com/mattsears18/shipyard/issues/1156)/[#1399](https://github.com/mattsears18/shipyard/issues/1399)). Mirrored to the session-state file and part of the [termination condition](./do-work/drain.md#termination-assertion).
- **`operator_queue`** (default-on; empty only under `--no-operate` / `--hands-off`): queue of **browser-completable operator actions** the orchestrator drains by driving the user's real Chrome. Entries: `{ id, source: "worker-handback" | "defer" | "survey", kind: "merge-pr" | "close-pr" | "toggle-setting" | "reply-comment" | "console-action" | "upload-file", target: "<url or #N>", plan: "<exact ordered browser steps>", origin_ref: "<#issue/#pr/defer that surfaced it>", rank_key }`. **Empty / unused only when `--no-operate` / `--hands-off` is set** (the operator layer is otherwise the default). Populated by two feeders — *reactive*: [steady-state.md step A.1](./do-work/steady-state.md#a1-parse-the-return-string) enqueues when a worker bail or an `external-dependency` / `agent-console` defer names a browser-completable action; *proactive*: [step D's refresh](./do-work/steady-state.md#d-periodic-refresh) runs a `/my-turn`-style sweep filtered to browser-completable items (including open issues carrying the `agent-console` label). Drained on the **main orchestrator thread** (serialized — the real browser is a singleton) in idle gaps and at each step-D tick by the [operator phase](./do-work/operate.md). Genuine human-judgment items are NOT enqueued — they stay hand-backs surfaced to `/my-turn` (the `needs-human-review` class). **`paste-secret` (any secret/credential-value write) is likewise never enqueued** ([#991](https://github.com/mattsears18/shipyard/issues/991)) — it's structurally undrainable regardless of backend, so both feeders classify and hand it back inline at candidate time instead of adding it to this queue; see [`operate/01-queue-and-authorization.md`'s enqueue-time hand-back](./do-work/operate/01-queue-and-authorization.md#secretcredential-value-writes-are-never-enqueued--hand-back-at-classification-time-991). Mirrored to the session-state file. Drained-to-empty is part of the [termination condition](./do-work/drain.md#termination-assertion).
- **`main_ci`**: cached snapshot of `<default-branch>` CI — `{ status: "green" | "red" | "pending" | "unknown", earliest_red_run_id?: string, earliest_red_run_url?: string, earliest_red_sha?: string, checked_at: <timestamp> }`. Refreshed by the divert-checks scan; consumed by the status line and the divert dispatch templates.
- **`session_prs`**: set of PR numbers this session opened, fix-checks-touched, or *adopted* as an inherited DIRTY PR. Populated by step A's reconcile (every `shipped` or fix-checks-touch appends `<M>`) and by [setup step 5.7](./do-work/setup/04j-failing-pr-snapshot.md#57-seed-inherited-dirty-prs-into-session_prs-cross-session-drain-hand-off) / [step D's failed-PR scan](./do-work/steady-state.md#d-periodic-refresh) (inherited `@me` PRs left `DIRTY`-but-green by a prior session — seeded so the end-of-session drain can dispatch a fix-rebase worker against them; closes [#373](https://github.com/mattsears18/shipyard/issues/373)). Read by the [end-of-session drain](./do-work/drain.md#end-of-session-drain) to decide what to watch and when to exit. The drain **drives** every entry toward a **completing** terminal state — **merged**, or a confirmed **external dependency** the agent cannot itself perform — re-triggering flakes, rebasing DIRTY PRs, and arming release PRs across polls (the concrete drive mechanics are phase c of #659, [#663](https://github.com/mattsears18/shipyard/issues/663); this phase defines the contract). Every other "settled" class — `blocked:ci`, rebase-capped, or still-pending at the `ci.max_drain_hours` ceiling (settle signal per [#374](https://github.com/mattsears18/shipyard/issues/374): pending with `headRefOid` unchanged for `ci.settled_minutes`, default 20) — is a **bounded-exit concession** that stops the drain from spinning forever but leaves the session **incomplete**, surfaced for the next run rather than reported as done ([#662](https://github.com/mattsears18/shipyard/issues/662)).
- **`deferred_issues`**: list of `{ issue: N, reason: "...", defer_reason_class: "external-dependency" | "human-decision-required" | "untrusted-author" | "confirmed-blocker-still-open" | "confirmed-non-shippable-as-single-PR" | "time-gated" | "blocked-by-in-flight-pr", evidence_pointer: "<mechanical citation>", provenance: "scope-agent" | "orchestrator-judgment" | "cached-diagnosis", deferred_at: "<iso-8601 UTC>", would_be_dispatchable_as_phase_1_if?: "...", blocking_prs?: [N, ...], would_be_ready_scope?: { files: [...], phase_1_scope?: "..." } }` entries for issues determined to be not-shippable-by-a-single-worker this session. `provenance` records *who* made the defer; `defer_reason_class` ([#298](https://github.com/mattsears18/shipyard/issues/298)) records *why* (one of seven strict values — entries missing it are spec violations); `evidence_pointer` ([#302](https://github.com/mattsears18/shipyard/issues/302)) records the mechanical citation grounding the chosen class (per-class shape table lives in [setup.md step 6](./do-work/setup/06-scope-preflight.md#6-initial-scope-pre-flight)'s Deferred shape docs — entries that don't match their class's shape are rejected at write time, not recorded). All three are required for the pre-drain re-validation pass (see [`drain.md` termination assertion](./do-work/drain.md#termination-assertion)). The optional `would_be_dispatchable_as_phase_1_if` (when scope-agent supplies it) names the condition that would unblock a phase-1 slice — read by [drain.md 5.b](./do-work/drain.md#5b--re-validate-scope-agent-and-cached-diagnosis-entries) to ask whether the unblock has happened. The orchestrator posts the reason (and phase-1 condition when present) as a comment on the issue, drops the issue from `raw_backlog`, and never dispatches a worker against it this session. For `confirmed-non-shippable-as-single-PR` defers it also applies the `needs-human-review` surfacing label plus the `<!-- do-work-needs-decomposition -->` body marker ([#498](https://github.com/mattsears18/shipyard/issues/498); re-keyed from the former dedicated `needs-decomposition` label to `needs-human-review` + the marker by [#519](https://github.com/mattsears18/shipyard/issues/519)'s binary-backlog fold) so the epic-handoff exits both the `/do-work` re-scope loop (the label is in setup step 4's dispatch-exclusion set) and reaches the `/my-turn` human queue, while the marker lets [`/decompose-epic`](./decompose-epic.md) still identify it as an auto-shardable epic among the broader `needs-human-review` pool; [drain.md 5.b](./do-work/drain.md#5b--re-validate-scope-agent-and-cached-diagnosis-entries) removes the label again if a fresh scope pass finds the issue ready. For `time-gated` defers ([#1165](https://github.com/mattsears18/shipyard/issues/1165)) it applies **no label at all** — instead it writes a `<!-- do-work-blocked-until: <date> -->` body marker **as the first line of the issue body — the [step-4 client-side filter](./do-work/setup/04-backlog-divert.md#4-fetch--rank-the-backlog) matches line 1 only, so a marker written anywhere else is a silent no-op** (the filter's own self-clearing marker, [#1161](https://github.com/mattsears18/shipyard/issues/1161); the line-1 requirement documented at write time by [#1434](https://github.com/mattsears18/shipyard/issues/1434)), so the issue drops out of the workable queue while the date is future and re-admits itself the instant it elapses, with no human review needed. **`external-dependency` defers additionally write that same `<!-- do-work-blocked-until: <date> -->` body marker — also as the first line of the body, same line-1-only constraint — alongside their `agent-console` label** ([#1195](https://github.com/mattsears18/shipyard/issues/1195)) — unlike `time-gated`'s human/agent-supplied date, this one is computed entirely orchestrator-side (`today + scope.external_dependency_recheck_days`, default 14 days) so it doesn't depend on the scope agent supplying one. It doesn't change dispatch eligibility (the `agent-console` label already excludes the issue from `raw_backlog`); its payoff is that the [proactive operator sweep](./do-work/operate/04-steady-state-hooks.md#d-hook--proactive-sweep--drain) skips re-enqueueing (and re-judging) the issue while the recheck date is still future, instead of re-litigating an unchanged upstream condition on every tick — see [RATIONALE → why external-dependency gets its own recheck marker (#1195)](./do-work-RATIONALE.md#step-6--why-external-dependency-gets-its-own-recheck-marker-issue-1195). **`blocked-by-in-flight-pr` defers ([#1426](https://github.com/mattsears18/shipyard/issues/1426))** record an issue that is fully scoped and shippable but would collide — textually or semantically — with files an OPEN PR still holds; the required companion field `blocking_prs: [N, ...]` names every holding PR the scope agent cited. Like `time-gated` and `confirmed-blocker-still-open`, it applies **no label** — there is no human decision to surface, only a still-open PR to wait out. **As of [#1429](https://github.com/mattsears18/shipyard/issues/1429), like `time-gated`, it also writes a self-clearing `<!-- do-work-blocked-by-prs: N,M -->` body marker** (step 4e in [06c-scope-handling-ui.md](./do-work/setup/06c-scope-handling-ui.md#handling-each-returned-entry-fires-as-each-background-agent-completes)) — `backlog-filter.sh classify`'s `--pr-collision-verdicts` map (populated by the new `eval-pr-collision` subcommand, wired unconditionally into [`classify-backlog.sh`](./do-work/setup/04-backlog-divert.md#4-fetch--rank-the-backlog)) drops the issue while any `blocking_prs` entry is still `OPEN` and re-admits it the instant every entry resolves to `MERGED`/`CLOSED` — **CAN become dispatch-eligible without waiting for pre-drain re-validation or a fresh session**, closing the "re-diagnose from scratch every session" waste #1426's Finding block describes. **As of [#1448](https://github.com/mattsears18/shipyard/issues/1448), the re-admission reuses the original scope agent's cached ready-shape scope when one was supplied AND it survives a mandatory semantic-premise re-validation against the merged PR's actual diff** — never on merge state alone, to avoid the exact stale-premise bug [#1426](https://github.com/mattsears18/shipyard/issues/1426) diagnosed (an acceptance criterion depending on a claim the holding PR had deleted). The optional `would_be_ready_scope` field (present only when the scope agent judged the issue would be immediately ready, same shape as a plain ready return's `files`/`phase_1_scope`) is persisted as a `<!-- do-work-blocked-by-prs-scope -->` comment ([06c-scope-handling-ui.md](./do-work/setup/06c-scope-handling-ui.md#handling-each-returned-entry-fires-as-each-background-agent-completes) step 4f); re-admission runs the full cache-reuse-or-fall-through procedure documented in [06f-pr-collision-cache-reuse.md](./do-work/setup/06f-pr-collision-cache-reuse.md), promoting straight to `ready_issues` from the cache when the premise re-validates and falling through to a **fresh** scope-agent dispatch otherwise (no cache, stale cache, or an invalidated/ambiguous premise). Surfaced in the end-of-session summary's own `Queued behind in-flight PRs:` line — separate from the plain `Deferred:` block, so a session saturated on file collisions doesn't misreport as backlog-stuck (see [cleanup-summary.md](./do-work/cleanup-summary.md#end-of-session-summary)). Every other class above is surfaced in the end-of-session summary's `Deferred:` block.

  Valid `provenance` values: **`"scope-agent"`** — scope pre-flight returned a `deferred`-shape result; drain re-validates per [drain.md 5.b](./do-work/drain.md#5b--re-validate-scope-agent-and-cached-diagnosis-entries) ([#299](https://github.com/mattsears18/shipyard/issues/299) closed the ground-truth gap; [#298](https://github.com/mattsears18/shipyard/issues/298) added the phase-slicing bias for re-validation; [#302](https://github.com/mattsears18/shipyard/issues/302) added the evidence-pointer requirement so speculative defers are caught at write time instead of waiting for the drain-time re-validation). **`"orchestrator-judgment"`** — orchestrator/human deferred in working memory without a scope agent; re-validated before drain per [drain.md's pre-drain re-validation pass](./do-work/drain.md#pre-drain-re-validation-of-deferred-entries). Orchestrator-judgment entries also carry `evidence_pointer` (typically a `Blocked by #N` reference or a one-line concrete citation matching the same per-class shape table); free-form working-memory defers without a mechanical citation are not written. **`"cached-diagnosis"`** — scope pre-flight detected a fresh marker-tagged diagnosis comment on the issue (within the `scope.diagnosis_reuse_hours` window, default 72h) whose mechanical evidence still re-validates cheaply; no scope agent was dispatched ([#563](https://github.com/mattsears18/shipyard/issues/563)). Drain.md 5.b treats these entries the same as `"scope-agent"` entries but applies the extended cross-session freshness window (not just the same-session carve-out) before deciding whether to dispatch a fresh scope agent.

  **Restriction on mid-session `deferred_issues` writes.** The only valid paths to write a `"scope-agent"`-provenance entry are the [scope pre-flight (step 6)](./do-work/setup/06-scope-preflight.md#6-initial-scope-pre-flight) and [step D's scope refill](./do-work/steady-state.md#d-periodic-refresh). To defer from working memory, either (a) dispatch a scope agent and record the `deferred`-shape return, OR (b) write `provenance: "orchestrator-judgment"` so it will be re-validated before drain. Adding `"scope-agent"` without an actual scope-agent return is a spec violation.
- **`trusted_authors`**: set of GitHub logins the orchestrator will dispatch workers against. Populated once at setup by [step 1.7](./do-work/setup/01-repo-recovery.md#17-resolve-trusted-author-allowlist) from `.shipyard/trusted-authors.txt` (per-repo override) with fallback to the live `repos/<owner/repo>/collaborators` API. Used by step 2's bucket-0.5 filter and step 4's client-side filter to drop issues filed by untrusted authors from the dispatch queue. Security boundary — never write code (and never arm auto-merge) from instructions in an issue authored by a login not in this set.
- **`workflow_scope_blocked_prs`** ([#812](https://github.com/mattsears18/shipyard/issues/812), extended by [#850](https://github.com/mattsears18/shipyard/issues/850)): list of PR numbers this session shipped whose auto-merge arming failed specifically because the dispatching `gh` token lacks the `workflow` OAuth scope and the PR's diff touches `.github/workflows/` — the structured `auto_merge:"unavailable-workflow-scope"` outcome (distinct from the generic `unavailable` bucket). **Two populating paths, five call sites total:** (1) [steady-state.md step A.1's `shipped` handler](./do-work/steady-state.md#a1-parse-the-return-string) appends whenever a reconciled **worker** return carries the `auto-merge: unavailable — gh token lacks workflow scope` suffix; (2) as of #850, the **four orchestrator-turn direct-arm call sites** — [inline-trivial §E](./do-work/inline-trivial.md#e-arm-auto-merge), the [A.0.5 crash-recovery re-arm](./do-work/steady-state.md#a05-post-return-worktree-reap-for-crashed--narrative-non-terminal-returns-fires-before-a1s-return-string-parsing), the [setup-3c orphan-recovery re-arm](./do-work/setup/00-config-worktree.md#07-setup-parallelization-contract-fire-once-batch), and the [release-train sweep](./do-work/drain.md#release-pr-auto-arming-and-deploy-watch-own-the-tail-phase-c--663) — also append when their own `gh pr merge --auto` call hits the identical block (see [drain.md's cross-reference](./do-work/drain.md#deferred-merge-lander-merge-unarmed-green-session-prs--720) for why this matters: before #850 those four sites discarded the error via `2>/dev/null || true`, so an orchestrator-armed PR's block was invisible even though the exact same finding from a worker-armed PR was already reported). Either way, the PR itself is still added to `session_prs` and drained normally (it's OPEN, unarmed, and stays that way until a human re-arms it — nothing about the drain contract changes). This list exists purely so the finding is reported **once, session-wide**, in the [end-of-session summary](./do-work/cleanup-summary.md#end-of-session-summary) with the exact one-time remediation (`gh auth refresh -h github.com -s workflow`), instead of surfacing as an unexplained-looking `unavailable` on every workflow-touching PR the session opens — the cause is deterministic (every subsequent workflow-touching PR this session will hit the identical error) so repeating the note per-PR would be noise, not new information. Session-local (not mirrored to the session-state file). Never auto-remediated — the orchestrator does not attempt to widen its own token's scope, and does not delegate the arm to a differently-scoped credential (no evidence any dispatch context on this host actually carries broader `gh` scope than the orchestrator's own token — see [do-work-RATIONALE.md](./do-work-RATIONALE.md#850--why-not-delegate-the-arm-to-a-worker) for why #850's "dispatch a trivial worker to arm it" suggestion was not adopted); re-arming is a one-time human action.
Plus a three-field **refresh tracker** that gates [step D](./do-work/steady-state.md#d-periodic-refresh)'s event-driven + adaptive-backoff cadence — `refresh_last_at` (timestamp), `refresh_last_snapshot` (`{ main_ci_status, failing_pr_count_all, failed_prs_size }`), and `refresh_zero_delta_streak` (integer). Not a dispatch-queue, just bookkeeping for the refresh trigger rules; see step D's [Refresh trigger rules](./do-work/steady-state.md#refresh-trigger-rules) for the full semantics.

A separate **`last_fresh_fetch`** timestamp ([#195](https://github.com/mattsears18/shipyard/issues/195)) tracks the most recent backlog re-fetch against the live tracker — set by step C's lightweight backlog re-check, step D's periodic refresh, or [drain.md's termination-assertion step 4](./do-work/drain.md#termination-assertion). Surfaced on the [steady-state step E invariant line](./do-work/steady-state.md#e-invariant-line-end-of-every-steady-state-turn) and gates handoff to drain — the orchestrator may not declare termination unless `last_fresh_fetch` is within the last 60s. Initial value `"never"` until the first re-check fires.

When a slot opens, the dispatch order is always: `divert_queue` first, then `failed_prs`, then `ready_issues` (subject to path-collision and lockfile rules). `deferred_issues` is **not** part of the dispatch order — deferred entries never become work for this session. The `operator_queue` is **not** a worker-dispatch source — it is drained by the orchestrator itself on the main thread (the operator phase), not by a dispatched subagent, and only when the operator layer is active (the default; disabled by `--no-operate` / `--hands-off`); see [`do-work/operate.md`](./do-work/operate.md).

## Session state file

The orchestrator mirrors every [orchestrator-state](#orchestrator-state) structure into a small JSON file at `$SHIPYARD_HOME/sessions/<session-id>.json` (default: `~/.shipyard/sessions/<session-id>.json`) — the durable record of the session, written through whenever state changes and removed at end-of-session by the cleanup step. The LLM's per-turn working memory still drives dispatch decisions; the file is the mirror, not the algorithm. The full JSON schema, the `session-state.sh` helper's complete subcommand reference, the 16-row write-through site table, the write-through failure mode, and the cost-tracking write-through rules (schema consumed once at `init`; the site table is a lookup pointing back into the phase files that perform each write) live in [`do-work/session-state-file.md`](./do-work/session-state-file.md) — load it on demand, not every turn. See [RATIONALE → Session state file](./do-work-RATIONALE.md#session-state-file--why-a-file-at-all) for the design discussion.

Three pieces stay reachable here because they're consulted on the reconcile hot path every turn — the two writes below (token attribution, plus state mirroring — `.in_flight` slot release and `.session_prs` shipped-return append fire on literally every reconcile turn) and the exit-code list they share ([step A.0](./do-work/steady-state.md#a0-attribute-the-dispatchs-token-usage-mandatory--before-any-return-string-parsing) and [step A reconcile](./do-work/steady-state.md#a-reconcile-the-return)):

```bash
# Bump token-usage counts after an Agent dispatch returns. --issue / --pr
# optional. --allow-degraded-init + --degraded-init-repo REQUIRED (see
# steady-state.md A.0). Strict path — harness <usage> exposes the breakdown:
plugins/shipyard/scripts/session-state.sh bump-tokens \
  --session-id "<session-id>" --issue <N> --pr <M> \
  --input <N> --output <N> --cache-read <N> --cache-creation <N> \
  --mode <mode> --model <model-id> --allow-degraded-init --degraded-init-repo "<owner/repo>"
# Degraded path (#279 — <usage> total-only): REPLACE the four breakdown flags
# with `--input <total_tokens> --degraded-total-only` (mutually exclusive; #320).

# Slot writes use the flag-shaped subcommands, never an `update --set` whose
# value is a JSON object literal -- post-relocation the worktree-isolation
# guard refuses that shape as "too complex to verify" and the durable record
# silently stops updating (issue #1561). set-slot at dispatch, release-slot
# at step B; both take the same degraded-init / repo-guard flags as update.
plugins/shipyard/scripts/session-state.sh set-slot \
  --session-id "<session-id>" --expected-repo "<owner/repo>" \
  --allow-degraded-init --degraded-init-repo "<owner/repo>" \
  --slot-id "<slot-id>" --kind issue --target "#<N>" \
  --agent-id "<agent-id>" --model "<alias-or-default>" --hard-path "<path>"
plugins/shipyard/scripts/session-state.sh release-slot \
  --session-id "<session-id>" --expected-repo "<owner/repo>" \
  --allow-degraded-init --degraded-init-repo "<owner/repo>" --slot-id "<slot-id>"

# Mirror any other state change (session_prs append, etc.). --set takes a
# jq expression, NOT a --path/--json pair (that's `read`'s shape, not update's).
# Keep values scalar/array or per-field (`.main_ci.status = "green"`); if an
# object literal is unavoidable, Write the expression to
# .shipyard-scratch/<name>.jq and pass `--set-file <path>` instead.
plugins/shipyard/scripts/session-state.sh update \
  --session-id "<session-id>" --expected-repo "<owner/repo>" \
  --allow-degraded-init --degraded-init-repo "<owner/repo>" \
  --set '.session_prs = ((.session_prs // []) + [<M>] | unique)'

# Record that THIS agent's own terminal return reached the reconcile
# (issue #1237) — a per-reconcile hot-path write, done once at the top of
# step A.1 before any per-mode handling. `.returned_agent_ids` is a MAP
# keyed by agent id, NOT an array — a `+ [...]` append (the session_prs
# shape above) fails with `jq: error: object ({}) and array (...) cannot
# be added`. worktree-reap.sh's `reap --action reaped` gate refuses to
# reap an agent-* worktree unless this key is set for that agent id (see
# do-work/steady-state.md's "Persist the return record" step for the full
# context and the --bypass-return-check exception classes):
plugins/shipyard/scripts/session-state.sh update \
  --session-id "<session-id>" --expected-repo "<owner/repo>" \
  --allow-degraded-init --degraded-init-repo "<owner/repo>" \
  --set '.returned_agent_ids["<agent-id>"] = "<RFC3339-timestamp>"'
```

`session-state.sh` exit codes (every subcommand, not just `bump-tokens`):

- `0` — success.
- `2` — `init` refused to clobber an existing file (use `--force` if the clobber is intentional). Protects against accidentally re-initialising a session that's still active.
- `3` — `read` or `update` ran on a session file that does not exist. Distinct from `0` so the orchestrator can branch on "first-write to a session that wasn't initialised" vs "successful read."
- `64` — usage error (bad subcommand, missing required arg). Mirrors `sysexits.h`'s `EX_USAGE`.
- `65+` — internal helper failure (jq missing, write permission denied). Never papered over — the orchestrator should surface these so the user sees why state stopped updating.

**Cost-tracking write-through — this is not optional, and the call site is [step A.0](./do-work/steady-state.md#a0-attribute-the-dispatchs-token-usage-mandatory--before-any-return-string-parsing), not this paragraph.** After every Agent dispatch returns, the orchestrator extracts the dispatch's `usage` payload and attributes it via `bump-tokens` (above) before reconciling the return string. The numbered first-step framing is load-bearing: a previous version of these docs described the hook only in prose, and the orchestrator silently skipped attribution across an entire 16-PR session ([#197](https://github.com/mattsears18/shipyard/issues/197)). The full attribution rules (issue/PR-scoped vs. orchestrator-overhead bumps, the observational-and-write-only posture, the Task Budgets non-equivalence) live in [`do-work/session-state-file.md`'s Cost-tracking write-through section](./do-work/session-state-file.md#cost-tracking-write-through).

### How to load on demand

Read only the phase file relevant to the current iteration — not all of them. **First turn** → [`setup.md`](./do-work/setup.md) (+ [`dont.md`](./do-work/dont.md) as a sidebar). **First completion arrives** → [`steady-state.md`](./do-work/steady-state.md). **Filling a worker slot (step 7 or step C)** → [`dispatch-rules.md`](./do-work/dispatch-rules.md) (the dispatch decision tree — load it just-in-time when you need to pick the next job, then drop it). **Step 3a flags an inline-eligible candidate AND `inline_trivial.enabled`** → [`inline-trivial.md`](./do-work/inline-trivial.md) (loaded just-in-time, not pre-loaded — inline-trivial is conservative-by-default and only fires when the heuristic clears). **All queues empty OR soft-drain triggered** → [`drain.md`](./do-work/drain.md). **Drain exits** → [`cleanup-summary.md`](./do-work/cleanup-summary.md). **Operator layer active (the default — unless `--no-operate` / `--hands-off`)** → [`operate.md`](./do-work/operate.md) for the preflight, loaded once at session start on every run except when `--no-operate` / `--hands-off` opts out. Its on-demand bodies under [`operate/`](./do-work/operate/) — queue/authorization, execution/playbooks, error-handling/safety, and the steady-state hooks — load only once `operator_queue` actually holds (or is about to hold) an item; see [`operate.md`'s own on-demand table](./do-work/operate.md#on-demand-bodies). The thin entry (this file) stays in context across every phase for the **hot** orchestrator-state struct list and the session-state pointer + `bump-tokens` call shape; the **cold** long-tail struct list ([`orchestrator-state-reference.md`](./do-work/orchestrator-state-reference.md)) and the full session-state schema/helper/write-through detail ([`session-state-file.md`](./do-work/session-state-file.md)) load on demand from the one phase file that needs them.

**Don't pre-load adjacent phases** ("this PR might fail CI, let me also load fix-checks rules"). Each phase's semantics are self-contained for that phase; pulling adjacent phases into context defeats the split. The orchestrator's next iteration loads whatever phase fires next.

## Don't

The load-bearing prohibition list lives in [`do-work/dont.md`](./do-work/dont.md) — read it as a sidebar alongside whatever phase is active. Headline categories: **dispatch-loop discipline** (no idling while queues hold work, no conflating "pool drained" with "session complete", no recap narration in lieu of dispatching, no polling), **dispatch hygiene** (`--label shipyard` on every `gh pr create`, respect soft-collision + lockfile-section rules), **failure-handling discipline** (never retry a `blocked:ci` PR, always verify a fix-checks `green` claim, never dispatch fix-rebase outside the drain), **worktree + filesystem discipline** (never write to the primary checkout, never reap a live-PID worktree, never omit the `shipyard:worker-preamble` skill reference), and **security boundary** (never dispatch against an untrusted-author issue, never rely solely on the dispatch-time author check — the [`label-event-audit.yml`](../../../.github/workflows/label-event-audit.yml) workflow audits routing-label mutation as defense-in-depth). See [`do-work/dont.md`](./do-work/dont.md) for the full list with rationale-link footnotes.
