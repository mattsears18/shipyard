# /shipyard:do-work — Cold orchestrator-state structures

Eighteen of the orchestrator's mental data structures — each **consumed by exactly one (or two closely-related) other phase file(s)**, not read on every turn by the dispatch loop itself. The thin entry [`commands/do-work.md`](../do-work.md) owns the [hot orchestrator-state struct list](../do-work.md#orchestrator-state) (the thirteen structures + refresh tracker every turn's dispatch decision touches) and a pointer to the [session state file](./session-state-file.md); this file owns the long-tail structures that a single consumer phase file reads and writes — the flake-detection circuit breaker, the classifier-denial ledgers, the operator hand-back ledger, the per-origin operator perception-retry budget, the stalled/failed-dispatch ledger, the session-state mirror's own degrade tracker, the phantom-notification dedup set, the CI-minute / primary-checkout-leak / environmental-pause counters, the batch-dispatch version cursor, the stale-required-check-refresh dedup map, and the fix-checks-only false-green telemetry + same-session escalation pair. **Reference block — consulted by the one phase file that owns each structure, not executed top-to-bottom every turn** — so it lives in its own file to keep the thin entry under a byte budget a fresh session reads on every turn ([#808](https://github.com/mattsears18/shipyard/issues/808), mirrors the [dispatch-rules.md split #616](./dispatch-rules.md)).

## Cold orchestrator-state structures

- **`main_ci_fix_attempts`** ([#589](https://github.com/mattsears18/shipyard/issues/589)): session-local map `{ <earliest_red_workflow_name> → { attempts: <int>, last_pr: <#M|null>, last_sha: <string|null>, escalated: <bool> } }` implementing the fix-main-ci attempt-cap / flake-detection circuit breaker — the fix-main-ci analogue of the `blocked:ci` 3-attempt cap for fix-checks. Keyed by `earliest_red_workflow_name` (the stable cross-attempt signature — `earliest_red_sha` changes on every merge commit so it can't be the key, but a fix-main-ci PR that goes green on its own PR run yet leaves main's *merge-commit* red on the **same workflow** is exactly the flaky-test pass-on-PR/fail-on-merge pattern this counter detects). `attempts` is incremented by [steady-state.md step A's fix-main-ci reconcile](./steady-state.md#a1-parse-the-return-string) each time a `shipped main-ci-fix` PR for a given workflow signature is followed by the same workflow re-reddening main on the next divert-checks refresh. When `attempts` reaches `main_ci.max_fix_attempts` (default 3, from `shipyard-config.sh`), the [step 4.5a enqueue rule](./setup/04-backlog-divert.md#45-divert-checks-main-ci--pr-pileup) stops enqueueing a `fix-main-ci` divert for that signature, sets `escalated: true`, and surfaces a structured flake escalation banner (recommend quarantine + tracking issue, or human CI-side investigation). Reset for a signature when main goes green on it (the fix worked) — a fresh red on a previously-escalated workflow starts a new attempt cycle only after a human clears the escalation by getting main green. Session-local (not mirrored to the session-state file). Read by [cleanup-summary.md's friction line](./cleanup-summary.md#end-of-session-summary) when any signature escalated.
- **`session_blocked_soft`** ([#300](https://github.com/mattsears18/shipyard/issues/300)): map `{issue_number → ISO-8601 UTC timestamp of the bail}` written by [steady-state.md step A.1's `blocked` handler](./steady-state.md#a1-parse-the-return-string) on soft-classified bails (cannot-reproduce / ambiguous / scope-judgment / PR-already-open), read by [step C's lightweight backlog re-check](./steady-state.md#c-dispatch-a-replacement-if-work-remains--mandatory-action) to skip in-window re-appends. Window = `blocked_agent.soft_retry_minutes` (default 30, from `shipyard-config.sh`); entries clear post-window; map is session-local (not mirrored to the session-state file). Refuse bails apply `needs-human-review` and dependency-wait bails apply no label (gated by the `Blocked by #N` body-reference filter) instead — the former `blocked:agent-hard` label was eliminated in [#521](https://github.com/mattsears18/shipyard/issues/521).
- **`reconciled_agent_ids`** ([#317](https://github.com/mattsears18/shipyard/issues/317)): set of harness `task-id` (a.k.a. `agent_id`) values for which step A has already run a full reconcile this session. Written by [steady-state.md step A's reconcile-once gate](./steady-state.md#a-reconcile-the-return) the moment a return has been parsed; read by the same gate at the **top** of every subsequent turn — when the incoming `task-notification`'s `task-id` is already in the set, the turn is a **phantom re-fire** and the orchestrator MUST silently skip A.0 / A.1 / B / C / D (no token bump, no slot release, no dispatch, no refresh, no invariant line). Session-local (not mirrored to the session-state file) and grows monotonically across the session — no eviction, since the set's only purpose is to recognize a duplicate that has already been fully accounted for. Defends against the observed Claude Code harness pattern where an agent's wind-down chat messages (e.g. "Done.", "Acknowledged.", "Monitor task completed.") arrive as additional `task-notification` events with the same `task-id` after the agent's actual return text was reconciled — see #317 for the repro and the harness-vs-orchestrator-fix tradeoff.
- **`ci_session_counters`** ([#323](https://github.com/mattsears18/shipyard/issues/323)): four-counter map `{ dispatches_skipped_stale_failure, dispatches_deferred_in_progress, drain_rebases_skipped, drain_rebases_dispatched }` tracking the CI-minute discipline gates introduced by the `ci.*` config block. Initialized to all-zero at session start, incremented inline by [steady-state.md step C's pre-dispatch checks](./steady-state.md#c-dispatch-a-replacement-if-work-remains--mandatory-action) (the stale-failure and in-progress-settle gates) and [drain.md's end-of-session drain](./drain.md#end-of-session-drain) (the skip-drain-rebase and max-drain-rebases gates). Session-local (not mirrored to the session-state file). Read by [cleanup-summary.md's `CI cost:` block](./cleanup-summary.md#end-of-session-summary) — surfaced only when at least one counter is non-zero OR at least one `ci.*` config key is non-default, so quiet sessions where the gates were off don't add summary noise. The four counters are intentionally disjoint surfaces (two for steady-state, two for drain) so a reader can attribute each saved CI suite to the specific gate that fired.
- **`primary_leak_counters`** ([#387](https://github.com/mattsears18/shipyard/issues/387)): two-counter map `{ primary_leak_restores, primary_leak_dirty_skips }` tracking how often the [primary-checkout branch-leak guard](./steady-state.md#a06-primary-checkout-branch-leak-guard-fires-every-reconcile-turn-before-a1) fired. The harness `isolation: "worktree"` dispatch path can leak a `do-work/*` branch checkout into the user's primary working tree; the guard (run every reconcile turn AND at [drain entry](./drain.md#end-of-session-drain)) restores a clean primary to the default branch (`primary_leak_restores`) or, when the primary tree is dirty, warns and skips without writing (`primary_leak_dirty_skips`). Initialized to all-zero at session start. Session-local (not mirrored to the session-state file). Read by [cleanup-summary.md's friction line](./cleanup-summary.md#end-of-session-summary) — surfaced only when the combined count is non-zero (silent on quiet sessions, per the `ci_session_counters` precedent).
- **`paused_on_environment_stats`** ([#1402](https://github.com/mattsears18/shipyard/issues/1402)): three-field counter `{ paused: <int>, resumed: <int>, expired: <int>, total_paused_minutes: <int> }` tracking how often — and for how long — this session entered a [`paused_on_environment`](../do-work.md#orchestrator-state) session-wide pause. `paused` increments each time [steady-state.md's "Session-wide environmental pause" trigger](./environmental-pause.md) fires; `resumed` / `expired` increment mutually exclusively, at the matching branch of the resume-notification handling, alongside the field being cleared to `null` — whichever fired adds the elapsed pause duration (in whole minutes) to `total_paused_minutes`. Initialized to all-zero at session start. Session-local (not mirrored to the session-state file) — unlike the live `paused_on_environment` entry itself (which IS mirrored, since a live pause must survive a state-file read mid-pause), this is purely a session-end tally, same posture as `ci_session_counters`/`primary_leak_counters`. Read by [cleanup-summary.md's summary block](./cleanup-summary.md#end-of-session-summary) — surfaced only when `paused > 0` (silent on quiet sessions, per the `primary_leak_counters` precedent).
- **`dispatch_denials`** ([#718](https://github.com/mattsears18/shipyard/issues/718)): list of `{ target: <#N | #M | "main" | "pr-pileup">, mode: "<issue-work|fix-checks-only|fix-rebase|fix-main-ci|fix-failing-prs-batch|investigate|spike>", denied_at: "<iso-8601 UTC>", denial_text: "<verbatim first line of the harness denial>", attempt: 1|2, outcome: "reframed" | "shipped-after-reframe" | "handed-back" }` entries recording every worker dispatch call — the `Agent` call under the default shape, or the `Workflow` call under the alternate shape (see [dispatch-rules.md § "Dispatch denied by the harness permission classifier"](./dispatch-rules.md#dispatch-denied-by-the-harness-permission-classifier-718)) — the **Claude Code auto-mode permission classifier refused outright**. Either way the dispatch tool call never happened, so there is no worker, no worktree, no `agent_id`, and no completion notification to reconcile. Written by the [denied-dispatch branch](./dispatch-rules.md#dispatch-denied-by-the-harness-permission-classifier-718) at both dispatch sites ([setup step 7](./setup/07-pool-fill.md#7-initial-pool-fill) and [steady-state step C](./steady-state.md#c-dispatch-a-replacement-if-work-remains--mandatory-action)). **Exactly one** re-dispatch is permitted per target, and only to correct a prompt that *overstated* the work's blast radius (the re-dispatch must make the prompt more **accurate**, never merely more permissive-sounding); iterating wording against the classifier is forbidden, and a second denial hands the target back to the human (`needs-human-review` for issue targets) rather than trying a third time. **Working-memory struct held for same-turn decisions; also mirrored to the durable session-state file** via `session-state.sh record-denial` (issue [#1302](https://github.com/mattsears18/shipyard/issues/1302)) — a single-entry, all-scalar-args typed subcommand, deliberately NOT a hand-built `.dispatch_denials = [...]` `--set` literal, because that shape is exactly what got denied outright by Auto Mode's classifier in the #1302 repro (nested-JSON `--set` payloads read to the classifier as a larger, less-verifiable mutation than a handful of scalar flags). The mirror call is fire-and-forget: a denied/failed mirror write does NOT block the turn or the working-memory append above — it sets the session-local `session_state_degraded_since` timestamp instead (see that entry below) so the degrade is visible on the invariant line rather than silent. Read by [cleanup-summary.md's `Dispatch denied:` line](./cleanup-summary.md#end-of-session-summary) so a denial is visible rather than silently costing a dispatch slot. Distinct from [#712](https://github.com/mattsears18/shipyard/issues/712)'s *worker-side* Bash denial (handled by the worker's `blocked:` return per `shipyard:worker-preamble` § "After a classifier denial") — this is the orchestrator's own dispatch call being refused.
- **`operator_denials`** ([#746](https://github.com/mattsears18/shipyard/issues/746)): list of `{ kind: "merge-pr" | "close-pr" | "paste-secret" | "toggle-setting" | "reply-comment" | "console-action" | "upload-file", target: "<url or #N>", denied_at: "<iso-8601 UTC>", denial_text: "<verbatim first line of the harness denial>", outcome: "reframed" | "shipped-after-reframe" | "handed-back" }` entries recording every **operator action** the Claude Code auto-mode permission classifier refused outright — the mutating call (`gh pr close`/`gh pr merge`/a browser mutation) never executed. Mirrors `dispatch_denials` (#718) but for the operator layer's queue-drain actions rather than worker dispatch calls; the two are recorded separately because the classifier denies them for different reasons (dispatch: widening the *worker's* permissions; operator: acting on an artifact outside the session's own scope). Written by [operate/01-queue-and-authorization.md's denied-operator-action branch](./operate/01-queue-and-authorization.md#operator-action-denied-by-the-harness-permission-classifier-746) whenever a queue-drain attempt is denied. **`kind: "paste-secret"` should never actually appear here** ([#991](https://github.com/mattsears18/shipyard/issues/991)) — a secret/credential-value write is never attempted (classified and handed back before it would ever be enqueued), so there is no attempt for the classifier to deny; the enum value is retained for shape-parity with `operator_handbacks` only. A `paste-secret` entry showing up in this list is itself a spec violation worth flagging, not a normal denial. **At most one** re-attempt is permitted per item, and only to cite an explicit user confirmation already on record (see [operate/01-queue-and-authorization.md's batched inherited-PR confirmation](./operate/01-queue-and-authorization.md#scope-of-standing-authorization--session-owned-artifacts-vs-inherited-third-party-prs-746)) — never to iterate wording against the classifier. A second denial (or no confirmation to cite) degrades the item to an `agent-console` hand-back rather than being retried or silently dropped from `operator_queue`. Session-local (not mirrored to the session-state file). Read by [cleanup-summary.md's `Operator denied:` line](./cleanup-summary.md#end-of-session-summary) so a swallowed operator action is visible rather than silently costing a queue item. **A production-class denial is recorded once, not once per item** ([#1563](https://github.com/mattsears18/shipyard/issues/1563)). It also sets the session-local `prod_class_stopped = { category, denied_at }` flag, which blocks every further production-class attempt this session. A sibling flag, `prod_class_confirmed`, records the batched "Run all" answer and plays the same role as `inherited_pr_confirmed`. See the [production-class gate](./operate/01-queue-and-authorization.md#production-class-console-actions--one-batched-confirmation-then-stop-the-class-after-a-denial-1563). Distinct from `dispatch_denials` (the orchestrator's own worker dispatch call being refused) and from [#712](https://github.com/mattsears18/shipyard/issues/712)'s worker-side Bash denial (a `blocked:` return from inside a dispatched worker) — this is the orchestrator's own **operator-phase** action being refused.
  **Retention past this session — opt-in, [#1363](https://github.com/mattsears18/shipyard/issues/1363).** Session-local working memory is discarded along with the session-state file when [cleanup-summary.md step 8](./cleanup-summary.md#end-of-session-cleanup) removes it — a denial's boundary information otherwise survives only if it happened to get hand-written into a PR/issue comment. When `operator_denial_registry.enabled` is `true` (default `false`), [cleanup-summary.md step 7.6](./cleanup-summary.md#end-of-session-cleanup) appends each of this session's `operator_denials` entries to the durable, cross-session `~/.shipyard/operator-denials.jsonl` ledger (via [`scripts/operator-denial-registry.sh`](../../scripts/operator-denial-registry.sh) `record`) BEFORE the session-state file is retired — mirroring how step 7 flushes `cost-history.jsonl` ahead of the same retirement, and giving this struct the same durable-mirror treatment `dispatch_denials`/`stalled_dispatches` get via `session-state.sh`, but as an append to a separate local-only file rather than a field inside the session-state JSON (a `target` here can be a specific admin-console URL, more identifying than either of those structs' payloads, hence the opt-in default rather than `flake_registry`'s own precedent). `operator-denial-registry.sh report --repo <owner/repo> --kind <kind>` aggregates the durable history by `(repo, kind, target)`, distinguishing a denial class seen once (a one-off) from one seen across multiple sessions (a standing constraint) via its `events` / `distinct_sessions` counts — [cleanup-summary.md's `Operator denied:` per-line rule](./cleanup-summary.md#end-of-session-summary) annotates a matching entry with this repeat signal when the registry is enabled. Disabled (default): behavior is unchanged from pre-#1363 — `operator_denials` is surfaced within this session's own summary only, same as every other session-local struct on this page.
- **`perception_retry_counts`** ([#1362](https://github.com/mattsears18/shipyard/issues/1362)): session-local map `{ <page origin, e.g. "https://console.cloud.google.com"> → <consecutive-failure int> }` implementing the per-surface retry budget for browser perception calls (`screenshot` / `read_page`) that time out on a page that never fires `document_idle` — a long-polling enterprise console can be fully rendered and interactive while still failing every idle-gated perception call. See [`operate/03-error-handling-and-safety.md`'s "Long-polling consoles that never reach `document_idle`"](./operate/03-error-handling-and-safety.md#long-polling-consoles-that-never-reach-document_idle--tool-preference-and-a-per-surface-retry-budget-1362) for the full mechanism: the tool-preference reordering, the `javascript_tool` readiness probe, and this counter. Keyed by **origin, not by session or by queue item** — so exhausting the budget against one console (e.g. `developers.facebook.com`) does not silently spend the budget for an unrelated one (e.g. `console.cloud.google.com`) reached later in the same session. Incremented on every idle-gated perception timeout matching the documented signature; a successful `javascript_tool`/`find` read against the same origin does NOT increment it, and any successful perception call against an origin resets that origin's counter to zero. Capped at 2 — the 3rd consecutive failure for an origin trips the hand-back (append to `operator_handbacks` with `reason: "never-idle"`, below) **from the counter value, not from in-the-moment judgment**. Initialized empty at session start. Session-local (not mirrored to the session-state file) — a fresh session has no history to protect and re-derives from scratch, same rationale as `stale_check_refresh_done` above.
- **`operator_handbacks`** ([#849](https://github.com/mattsears18/shipyard/issues/849)): list of `{ kind: "merge-pr" | "close-pr" | "paste-secret" | "toggle-setting" | "reply-comment" | "console-action" | "upload-file", target: "<url or #N>", reason: "no-browser-backend" | "dry-run" | "security-class" | "logged-out" | "never-idle" | "values-only-user-has" | "denied-by-classifier" | "judgment-call" | "prod-class-unattended" | "prod-class-stopped", origin_ref: "<#issue/#pr/defer that surfaced it>", current_label: "agent-console" | "needs-human-review", handed_back_at: "<iso-8601 UTC>" }` entries recording **every browser-completable-in-principle candidate that did not end this session driven to completion** — the general hand-back ledger `operator_denials` (#746) is a narrower special case of (it records only the classifier-refused subset, and only the refusal transcript, not the reason a candidate still didn't get driven). Appended by every hand-back exit inside the operator phase: the [security/access-control carve-out](./operate/02-execution-and-playbooks.md#claude-safe-to-auto-drive-vs-hand-back-securityaccess-control) (`reason: "security-class"`, alongside the `agent-console` → `needs-human-review` relabel), a logged-out console on `toggle-setting`/`verify` (`reason: "logged-out"`), a long-polling console whose `perception_retry_counts` origin entry hit the 2-failure cap (`reason: "never-idle"`, per [operate/03-error-handling-and-safety.md](./operate/03-error-handling-and-safety.md#long-polling-consoles-that-never-reach-document_idle--tool-preference-and-a-per-surface-retry-budget-1362) — the item stays on `agent-console`, unlike the relabeling reasons above), a `reply-comment` discovered mid-drain to need human evaluation (`reason: "judgment-call"`), and the second-denial degrade path in [01-queue-and-authorization.md](./operate/01-queue-and-authorization.md#operator-action-denied-by-the-harness-permission-classifier-746) (`reason: "denied-by-classifier"`, written in the same step that appends to `operator_denials`). The [production-class gate](./operate/01-queue-and-authorization.md#production-class-console-actions--one-batched-confirmation-then-stop-the-class-after-a-denial-1563) ([#1563](https://github.com/mattsears18/shipyard/issues/1563)) adds two more reasons: `prod-class-unattended`, for items handed back without an attempt because no one was present to confirm them, and `prod-class-stopped`, for items handed back after a `Modify Shared Resources` or `Production Reads` denial stopped the class. **A `paste-secret` (any secret/credential-value write) tee-up (`reason: "values-only-user-has"`) is the one exception to "appended from a popped `operator_queue` item"** — it is written **at classification time**, before the candidate would ever have been enqueued ([#991](https://github.com/mattsears18/shipyard/issues/991); see [01-queue-and-authorization.md's enqueue-time hand-back](./operate/01-queue-and-authorization.md#secretcredential-value-writes-are-never-enqueued--hand-back-at-classification-time-991)) — a secret/credential-value write never sits in `operator_queue` at all, so there's no pop to append from. Two further reasons are populated **not** by a drain-time append but by [cleanup-summary.md's own read](./cleanup-summary.md#end-of-session-summary) at session end, because the item was never popped from `operator_queue` at all: any item still sitting in `operator_queue` when [preflight found no browser backend](./operate.md#degradation--no-backend-reachable) (`reason: "no-browser-backend"`) or when the session ran under `--dry-run` (`reason: "dry-run"`) — cleanup-summary treats these leftover queue entries as synthetic `operator_handbacks` rows for rendering purposes without a separate write. Session-local (not mirrored to the session-state file). Read by [cleanup-summary.md's `Operator queue — needs you (N):` block](./cleanup-summary.md#end-of-session-summary), which unions this list with any items still left in `operator_queue` and omits the block entirely when the union is empty.
- **`stalled_dispatches`** ([#838](https://github.com/mattsears18/shipyard/issues/838) / [#833](https://github.com/mattsears18/shipyard/issues/833)): list of `{ target: "#<N|M>", mode: "<issue-work|fix-checks-only|fix-rebase|fix-main-ci|fix-failing-prs-batch|investigate|spike>", trigger: "non-terminal-return" | "harness-failed", outcome: "resumed" | "handed-back" | "dropped-clean", resumed_pr: <#M|null>, detected_at: "<iso-8601 UTC>" }` entries recording every occurrence of [steady-state.md step A.0.5's](./steady-state.md#a05-post-return-worktree-reap-for-crashed--narrative-non-terminal-returns-fires-before-a1s-return-string-parsing) inspect-before-reap flow — a worker stopping with a pending-intent narrative return (`trigger: "non-terminal-return"`, the #838 case) or the harness declaring the dispatch `status: failed` via the stall watchdog (`trigger: "harness-failed"`, the #833 case). `outcome: "resumed"` is appended by the stalled-worker resume path (step 1–5 of A.0.5's "Stalled-worker detection and resume" subsection) the moment a resume is dispatched — via `SendMessage` to the same `agent_id` for a live `Agent`-tool subagent, or a fresh `agent()` call into the same worktree/branch for a `Workflow`-substrate dispatch — and its `resumed_pr` field is back-filled once the resume itself returns a terminal string. `outcome: "handed-back"` is appended by the crash-recovery fallback when the resume cap (1 per target per session) is already exhausted or the trigger was a genuine crash, but the pre-reap salvage (#493/#495) still recovered committed-but-unpushed or dirty-worktree work into a PR (`resumed_pr` set to that PR's number). `outcome: "dropped-clean"` is appended when the same fallback found nothing recoverable (the worktree was clean) — this is the retryable, no-label case: the slot is dropped and step C's next fill retries the candidate fresh, mirroring the plain dispatch-refused shape. Mirrors `dispatch_denials` (#718) and `operator_denials` (#746) in structure and intent — a stalled/failed dispatch should never silently cost a slot with nothing in the session's output explaining why. **Working-memory struct; also mirrored to the durable session-state file** via `session-state.sh record-stall` (issue [#1302](https://github.com/mattsears18/shipyard/issues/1302)), same single-entry typed-call rationale as `dispatch_denials` above — see that entry for why the payload is kept small and how a denied/failed mirror write is surfaced (`session_state_degraded_since`) instead of blocking the turn. The mirrored copy's `resumed_pr` is NOT back-filled after a resume ships (the typed subcommand only appends; there is no update-in-place) — the working-memory struct and the end-of-session summary remain the fidelity source for that field. Read by [cleanup-summary.md's `Stalled dispatches (#838/#833):` line](./cleanup-summary.md#end-of-session-summary), which omits the block entirely when the list is empty.
- **`session_state_degraded_since`** ([#1302](https://github.com/mattsears18/shipyard/issues/1302)): nullable session-local timestamp `"<iso-8601 UTC>" | null` — `null` for the entire session unless a write-class `session-state.sh` call (`update`, `bump-tokens`, `record-stall`, `record-denial`, or any other write subcommand) either returns non-zero or is refused outright by Auto Mode's classifier before it ever runs. Set to the UTC timestamp of the **first** such occurrence and held — deliberately NOT itself written into the session-state file, since the file is exactly what might be unreachable at the moment this needs recording (the chicken-and-egg problem the issue's own write-up calls out: "both fields are written exactly when a session is already going sideways — the worst possible moment for the write itself to fail"). Read by [steady-state.md step E's invariant line](./steady-state.md#e-invariant-line-end-of-every-steady-state-turn), which MUST keep emitting `state=degraded` on every turn this field is non-null — never silently reverting to `written`/`noop` — until a write-class call actually succeeds again, at which point the orchestrator clears the field and logs `[session-state] mirror recovered — was degraded since <timestamp>`. Also read by [cleanup-summary.md's "Session-state mirror degraded" block](./cleanup-summary.md#end-of-session-summary), which reports the onset timestamp (and recovery timestamp, if the mirror recovered before session end) so a human reviewing the session knows exactly which window of `/shipyard:status` reads (and, for a session that never recovers, every subsequent read) reflected stale state. The one field in this file that is explicitly NOT "session-local (not mirrored)" in the sense the other entries mean it — it exists specifically because the mirror *itself* can go stale, so its own bookkeeping has to live somewhere the mirror's own failure can't take down.
- **`stale_check_refresh_done`** ([#993](https://github.com/mattsears18/shipyard/issues/993)): session-local map `{ <pr-number> → <default-branch HEAD sha> }` guarding the post-main-CI-fix branch-refresh mechanism against repeated `gh pr update-branch` calls against the same PR for the same fix. Written by [04-backlog-divert.md's post-main-CI-fix branch-refresh](./setup/04h-post-main-ci-branch-refresh.md#post-main-ci-fix-branch-refresh--un-stick-session-prs-carrying-a-stale-failing-required-check-993) (fires from setup's 4.5a and from [step D's periodic refresh](./steady-state.md#d-periodic-refresh)) and by [drain.md's per-poll equivalent](./drain.md#post-main-ci-fix-branch-refresh-drain-phase-993) — the same map, shared across both call sites so a PR refreshed once during steady-state isn't refreshed again during drain for the identical fix commit. - **`version_cursor`** ([#437](https://github.com/mattsears18/shipyard/issues/437)): session-local high-water mark of the highest manifest version slot **computed by dispatch** — distinct from the open-PR walk the [#339 next-available-version computation](./dispatch-rules.md#dispatch-rules-used-by-step-7-and-step-c) does. The #339 walk only sees versions claimed by **open** PRs, which is blind to siblings dispatched in the same batch (initial pool fill at [setup.md step 7](./setup/07-pool-fill.md#7-initial-pool-fill), or any step C multi-fill): those PRs aren't open yet, so every worker in the batch reads the same floor (main's version) and the per-dispatch walk hands them all the same `next_available_version` — the first C≥2 batch all claims `main+1` and N−1 PRs go DIRTY on the version row. The cursor closes that gap: the version computation seeds from `max(version_cursor, session_prs-walk-result)` and **advances the cursor to the value it hands out**, so a batch of N simultaneous dispatches receives distinct monotonic slots (`main+1`, `main+2`, … `main+N`) even before any PR is open. Initialized to `null`/unset at session start (no claim yet); only consulted when `version_coordination.enabled` and a `manifest_path` is configured (otherwise the cursor is never read or written). Session-local (not mirrored to the session-state file) — the cursor only matters within a live session's batch-dispatch window; a fresh session re-derives the floor from `origin/<default-branch>`'s manifest.
  - **Self-healed mid-session, not just at session boundaries ([#1417](https://github.com/mattsears18/shipyard/issues/1417)).** The cursor advances on what `compute` *predicted* a worker would ship, not on what the worker actually *claimed* — a worker legitimately taking a different bump level than the orchestrator inferred (issue #671's "the level is yours to raise" contract) leaves the predicted slot's value stuck in the cursor forever, and every later `compute` floors above that phantom. `next-available-version.sh reseed-if-idle`, called once per dispatch-decision round (never inside a batch's own sequential per-slot loop — see the script's header and [dispatch-rules.md](./dispatch-rules.md#dispatch-rules-used-by-step-7-and-step-c)), discards the persisted cursor whenever `session_prs` has no currently-OPEN member — self-healing the drift the moment everything that could have claimed the phantom slot has drained, without touching `compute`'s own fold-in logic (which stays unconditional, load-bearing for batch monotonicity). This is a partial fix: it recovers at drain points, not at the instant a divergence happens — see [`do-work-RATIONALE.md`](../do-work-RATIONALE.md#version_cursor-self-heal--why-reseed-if-idle-is-a-separate-once-per-round-call-and-why-full-claim-tracking-option-1-was-deferred-issue-1417) for why a full claim-tracking fix was deferred.
  - **Released at reconcile when a dispatch never claims its slot ([#1420](https://github.com/mattsears18/shipyard/issues/1420)).** The other leak variant — and the one `reseed-if-idle` structurally cannot reach, since it fires only when `session_prs` has no OPEN member while this leak happens with siblings still open. `compute` advances the cursor the instant it hands a slot out; a dispatch that then terminates without opening a PR (a `blocked` return, a permission-classifier denial, a crash, an explicit decline) leaves that value stranded. [Step B.0](./steady-state.md#b-release-the-slot) releases it, reading the promise back off `.in_flight[<slot-id>].version_slot`. **The release never lowers the cursor** — a released slot may not be the highest one outstanding, and decrementing would hand a later batch member's already-promised value back out, reintroducing the [#437](https://github.com/mattsears18/shipyard/issues/437) collision. The value is instead recorded in a **holes companion file** (`<cursor-file>.holes`, same session-local lifetime and gitignored-by-location posture as the cursor itself), and the next `compute` hands it back out — reporting it as `reclaimed_slot` — only when it sits strictly above the floor derived from ground truth alone (origin's manifest + the open-PR walk). A skipped release degrades to the pre-#1420 status quo (a leaked slot), never to a collision. Surfaced per-turn as [`version_release=<n/a|none|released|skipped>`](./invariant-line.md); see [`do-work-RATIONALE.md`](../do-work-RATIONALE.md#release-on-non-claim--why-a-released-slot-becomes-a-hole-instead-of-a-cursor-rollback-and-why-that-needs-no-per-slot-promise-ledger-issue-1420).
  - **Surfaced on the invariant line ([#1417](https://github.com/mattsears18/shipyard/issues/1417)).** [Step E](./steady-state.md#e-invariant-line-end-of-every-steady-state-turn) reports the cursor's current on-disk value every turn as `version_cursor=<X.Y.Z|"unset"|n/a>` — see [`invariant-line.md`](./invariant-line.md) for the token's full semantics and divergence smell. Unlike the other cold structs in this list, this one is cheap enough (a local file read) to surface on every turn rather than only in the end-of-session summary.
