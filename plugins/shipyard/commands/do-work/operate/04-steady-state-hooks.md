## Operator layer hooks into the steady-state loop

*(Default-on — under `--no-operate` / `--hands-off`, ignore this entire section.)*

On every run except the `--no-operate` / `--hands-off` opt-out, the steady-state loop has a browser-operator layer. The full machinery — backend selection, preflight, standing authorization, per-kind playbooks, the `operator_queue` drain loop, and the proactive sweep — lives in the rest of the operator phase ([the `operator_queue` and its two feeders](../operate/01-queue-and-authorization.md#the-operator_queue-and-its-two-feeders), [playbooks by kind](../operate/02-execution-and-playbooks.md#playbooks-by-kind)); this section is just the two hooks the steady-state loop owns. Under `--no-operate` / `--hands-off`, ignore this entire section: `operator_queue` stays empty and nothing here fires.

### A.1 hook — reactive enqueue

When parsing a worker return in [step A.1](../steady-state.md#a1-parse-the-return-string), if the bail/defer names a **browser-completable** action (a `blocked:`/`deferred:` reason that is an operator action — approve a deployment, toggle a console, a worker **`external provisioning required`** bail that needs an account created / credential set ([#628](https://github.com/mattsears18/shipyard/issues/628)), a worker **`irreversible external action`** bail that names the exact delete / access-widening command it declined to run itself ([#1519](https://github.com/mattsears18/shipyard/issues/1519)) — or a scope-agent **`external-dependency`** defer), enqueue an `operator_queue` item `{ source: "worker-handback"|"defer", kind, target, plan, origin_ref }` in addition to the normal recording. When the operator layer is active (the default — unless `--no-operate` / `--hands-off`), the [setup step-6 recording path](../setup/06-scope-preflight.md#6-initial-scope-pre-flight) already routes `external-dependency` defers to the `agent-console` label; the enqueue is the in-session working copy the orchestrator drains this session. **Genuine `human-decision-required` / judgment defers are NOT enqueued** — they stay `needs-human-review` hand-backs.

**A bail/defer whose action is a secret/credential-value write — "paste a secret," "store a deploy-hook URL in Secret Manager," any `create`/`set`/`add`/`update` on a secret store — is NOT enqueued either** ([#991](https://github.com/mattsears18/shipyard/issues/991)). It is structurally undrainable regardless of backend (browser or an authenticated CLI, piped or not), so recognize the shape right here at parse time and skip straight to the hand-back: run the read-only verification/remediation-composition inline, post it, and append to `operator_handbacks` (`reason: "values-only-user-has"`) — never create an `operator_queue` entry for it. See [01-queue-and-authorization.md's enqueue-time hand-back](../operate/01-queue-and-authorization.md#secretcredential-value-writes-are-never-enqueued--hand-back-at-classification-time-991) for the full rationale and the [`paste-secret` playbook](../operate/02-execution-and-playbooks.md#playbooks-by-kind) for the read/compose/hand-back mechanics.

### D hook — proactive sweep + drain

In [step D's periodic refresh](../steady-state.md#d-periodic-refresh), additionally:

1. **Proactive sweep.** Run a `/my-turn`-style discovery filtered to the **browser-completable subset** — open issues carrying the **`agent-console`** label (renamed from `needs-operator` in [#995](https://github.com/mattsears18/shipyard/issues/995); the legacy-name back-compat window is closed per [#1082](https://github.com/mattsears18/shipyard/issues/1082)), superseded/duplicate PRs to close, a referenced provider toggle, an *unambiguous* drafted reply — and enqueue any not already in `operator_queue`. Judgment calls are never enqueued. **Neither are secret/credential-value writes** (CI secrets flagged by a red run, or any `agent-console` issue whose action is a secret paste/store) — classify and hand those back inline during the sweep itself instead of enqueueing (same rule as the A.1 hook above; [#991](https://github.com/mattsears18/shipyard/issues/991)).

   **Skip an `agent-console` issue whose body carries a still-future `<!-- do-work-blocked-until: YYYY-MM-DD -->` recheck marker ([#1195](https://github.com/mattsears18/shipyard/issues/1195)).** The [setup step-6 recording path](../setup/06-scope-preflight.md#6-initial-scope-pre-flight) now writes this marker on every `external-dependency` defer (in addition to the label — see [step 4b](../setup/06c-scope-handling-ui.md#handling-each-returned-entry-fires-as-each-background-agent-completes)), naming the date before which nothing has plausibly changed upstream. Before enqueueing (or re-judging) an `agent-console` candidate, read its body's first line; if it matches the marker and the date is still in the future (`today < date`, UTC), skip it this tick — do NOT enqueue it, do NOT re-derive whether it's now actionable — and log `[operator] #<N> skipped — recheck marker not yet elapsed (<date>)`. Once the date elapses, the issue is swept normally again on the next tick. This is a rate-limiter on re-evaluation only; it does not clear the label or otherwise change the issue's disposition. An `agent-console` issue with no marker (the common case for a genuine, immediately-actionable provisioning/console item) is swept every tick exactly as before this change.

   **Before applying a `<!-- do-work-blocked-until: YYYY-MM-DD -->` calendar skip to an `agent-console` issue, evaluate a companion recorded-probe marker if one is present ([#1198](https://github.com/mattsears18/shipyard/issues/1198), extending the calendar-only gate [#1195](https://github.com/mattsears18/shipyard/issues/1195) added).** A `<!-- do-work-blocked-until: -->` marker (any class that writes one — currently `time-gated`; `external-dependency` gets the same marker once [#1199](https://github.com/mattsears18/shipyard/issues/1199) lands) can optionally be paired with a second, independent body marker: `<!-- do-work-recheck: <verb> <args...> -->`, naming a mechanically-checkable command that tests the actual blocking condition instead of just waiting out a date. When `scope.recheck_probe_enabled` is `true` (the default) and the issue body contains this marker, evaluate it BEFORE the plain date comparison:

   ```bash
   export CLAUDE_PLUGIN_ROOT="${CLAUDE_PLUGIN_ROOT:-$(R=$(git rev-parse --show-toplevel 2>/dev/null); if [ -d "$R/plugins/shipyard/scripts" ]; then echo "$R/plugins/shipyard"; else I=$(jq -r '.plugins["shipyard@shipyard"][0].installPath // empty' "$HOME/.claude/plugins/installed_plugins.json" 2>/dev/null); if [ -n "$I" ] && [ -d "$I/scripts" ]; then echo "$I"; else echo "$R/plugins/shipyard"; fi; fi)}"
   
   VERDICT=$(gh issue view <N> --repo <owner/repo> --json body --jq '.body' \
     | "$CLAUDE_PLUGIN_ROOT/scripts/eval-recheck-probe.sh" <owner/repo>)
   ```

   `eval-recheck-probe.sh` is the **single executable source of truth** for this decision — it parses the marker against a small, hardcoded verb allowlist (`npm-view`, `gh-api`, and — since [#1496](https://github.com/mattsears18/shipyard/issues/1496) — `url-json`, a read-only HTTPS GET whose host must appear in the repo's committed `scope.recheck_probe_url_hosts` array, which is EMPTY by default so the verb is inert until a repo deliberately opts in), rejects anything that doesn't match one of the three fixed grammars (never attempting to sanitize free-form text), executes the matched probe as a fixed-binary argv array with a bounded timeout, and returns exactly one of four verdicts:

   - **`absent`** (no `do-work-recheck` marker present) → fall through to the plain `do-work-blocked-until` date comparison, unchanged from before this marker existed.
   - **`unchanged`** (the probe ran and matched the recorded value) → same as `absent` — the blocking condition still holds by this evidence; apply the plain date comparison.
   - **`changed`** (the probe ran and did NOT match the recorded value) → the upstream fact has moved. Re-enqueue the issue for a fresh look on THIS tick, regardless of whether the `blocked-until` date is still in the future — this is the one case that brings re-evaluation forward.
   - **`unknown`** (marker malformed, or the probe errored / timed out / returned nothing) → same as `absent`/`unchanged` — fall through to the plain date comparison. **Never treat `unknown` as `changed`** — an inconclusive read must never bypass the calendar gate.

   See the script's own header comment for the full marker grammar, the threat model (the marker is untrusted issue-body text — see the file's own docstring for why every field is allowlist-validated before it ever reaches `npm`/`gh`/`curl`, never shell-interpolated), and [RATIONALE → recorded-probe recheck marker (#1198)](../../do-work-RATIONALE.md#step-d--recorded-probe-recheck-marker-for-external-dependency-defers-issue-1198) for the design rationale. **Authorship is either human-written (a maintainer hand-writes the marker into the issue body, the same trust posture as a human hand-writing a `do-work-blocked-until` marker per the [step-4 dispatch filter](../setup/04-backlog-divert.md#4-fetch--rank-the-backlog)'s own precedent, [#1161](https://github.com/mattsears18/shipyard/issues/1161)) or scope-agent-authored** — [`06d-recheck-probe-authorship.md`](../setup/06d-recheck-probe-authorship.md) ([#1201](https://github.com/mattsears18/shipyard/issues/1201), widened beyond `external-dependency` by [#1356](https://github.com/mattsears18/shipyard/issues/1356) to also cover `time-gated`) lets the scope agent's own `evidence_pointer` seed a validated marker automatically at defer-recording time, whenever the blocking condition is mechanically checkable — this proactive operator sweep's read side treats either provenance identically, since `eval-recheck-probe.sh` re-validates the marker text on every evaluation regardless of who wrote it.

   **This same `do-work-recheck` marker also governs the ordinary dispatch-eligibility filter, not only this operator sweep ([#1356](https://github.com/mattsears18/shipyard/issues/1356)).** `scripts/backlog-filter.sh classify`'s `eval-probes` precompute step evaluates it for ANY issue in the backlog fetch, regardless of label — an issue never routed through `agent-console` (most `time-gated` defers, for instance) still gets its probe evaluated at [step-4 dispatch time](../setup/04-backlog-divert.md#4-fetch--rank-the-backlog), where an unresolved verdict drops the issue as `event-gated` rather than `time-gated`, and — critically — never re-admits it via the calendar alone even after the paired `do-work-blocked-until` date elapses. This sweep's own read path (below) and `classify`'s read path are two independent consumers of the identical marker and the identical `eval-recheck-probe.sh` evaluator; they cannot disagree on a single issue's verdict, only on which QUEUE that issue is evaluated for (the operator queue here vs. the ordinary dispatch backlog there).

2. **Drain.** Whenever the orchestrator is otherwise idle (a code worker is in flight and not yet returned, or this is a step-D tick), pop the highest-`rank_key` `operator_queue` item and execute it **on the main thread** via the [operator phase playbooks](../operate/02-execution-and-playbooks.md#playbooks-by-kind) — serialized, one browser action at a time (the real browser is a singleton; never dispatch a subagent to drive it). On success, remove the item and clear the issue's `agent-console` label; on a hand-back outcome (e.g. a value only the user holds, or a logged-out console), [`verify`](../operate/02-execution-and-playbooks.md#playbooks-by-kind)-read the console first to make the hand-back concrete (confirm the premise, name the exact toggles/values), then leave the label and surface it. When a human has completed a handed-back action mid-session, a `verify` re-read reports pass/fail and a verified pass is what clears the `agent-console` label and closes the originating issue. Write-through `operator_queue` to the session-state file on each enqueue/drain.

If preflight found no browser backend, the drain is a no-op: items accumulate and are surfaced as hand-backs at end of session ([Degradation](../operate.md#degradation--no-backend-reachable)).
